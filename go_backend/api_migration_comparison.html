مقارنة APIs بين solar_hub (Django Ninja) و go_backend (Go/Gin)

تقرير شامل لكل endpoints موجودة في solar_hub ومدى نقلها إلى go_backend، مع مقارنة الـ Auth / Params / Body / Response.

1. الملخص التنفيذي

المؤشر العدد
إجمالي APIs في solar_hub 227 endpoint
تم نقلها بالكامل أو جزئياً إلى go_backend 157 endpoint
لم يتم نقلها بعد 70 endpoint
نسبة الإنجاز التقريبية ~69%

الحالة الملونة

  • مطابق مطابق — المسار والـ Method والـ Auth والمدخلات والمخرجات متطابقة أو شبه متطابقة.
  • جزئي جزئي — تم نقل الـ endpoint لكن يوجد اختلافات في المدخلات/المخرجات أو الصلاحيات.
  • غير منقول غير منقول — لا يوجد مقابل له في go_backend.

15. الاختلافات الجوهرية التي تحتاج تصحيح

15.1 endpoints متبقية داخل Companies

  • لا توجد endpoints متبقية داخل Companies — تم نقل الكل.

15.2 وحدات كاملة لم تُنقل

  • لا توجد وحدات كاملة متبقية — تم نقل كل الـ endpoints.

15.3 توحيد المسارات والمخرجات بعد المقارنة المباشرة

  • Swagger / Docs: تم نقل Swagger UI من /api/swagger/* إلى /api/v1/docs/* ليطابق حقل documentation في Django (/api/v1/docs).
  • API Root (GET /api/v1/): تم تعديل مخرجات Go لتطابق Django بالضبط: {"status":"active","message":"Welcome to Watt App API","version":"1.0","documentation":"/api/v1/docs"}.
  • JWT Secret: تم توحيد الـ default secret في Go مع Django (django-insecure-x)...) بحيث تكون التوكنات متبادلة في بيئة التطوير.
  • Public Companies (GET /api/v1/public/companies/): تم تصحيح شكل الـ body ليطابق Django (items, total, page, pages, has_next, has_previous) بدلاً من التداخل تحت pagination.
  • Public Posters (GET /api/v1/public/companies/posters): تم إرجاع المصفوفة مباشرة (raw array) كما يفعل Django، مع إضافة الحقول المفقودة (company_name, status, is_active, approved_at, updated_at).
  • Public Company Works (GET /api/v1/public/companies/{id}/works): تمت إضافة has_next و has_previous للـ pagination.
  • Systems (GET /api/v1/systems/): تم تصحيح شكل الـ body ليطابق Django (items, total, page, pages, has_next, has_previous) وتغيير الرسالة إلى Success.
  • Company Types (GET /api/v1/companies/types): تم تغيير الرسالة إلى Company types retrieved successfully..
  • Admin Countries / Cities (GET /api/v1/admin/countries و /api/v1/admin/cities): تم إرجاع المصفوفة مباشرة (raw array) كما يفعل Django.
  • Admin Lists (GET /api/v1/admin/categories, /api/v1/admin/subscriptions, /api/v1/users): تم إرجاع كائن {items, count} مباشرة بدلاً من التغليف العام.
  • Notification Devices (GET /api/v1/notification/devices): تم إرجاع كائن {devices, count} مباشرة بدلاً من التغليف العام.
  • Company Delivery / Contacts (GET /api/v1/companies/{id}/delivery و /contacts): تم إرجاع كائن {items, count} مباشرة بدلاً من التغليف العام.
  • توحيد الـ Trailing Slash: تمت إضافة middleware في Go يقبل الطلبات بشرطة نهائية أو بدونها (/api/v1/users = /api/v1/users/)، بحيث يتطابق سلوك المسارات مع Django. صفحة Swagger تُعرض عبر /api/v1/docs → /api/v1/docs/index.html.
  • ملاحظة عامة: الاختلافات المتبقية في البيانات الفعلية أو الـ permissions ترجع إلى استخدام قواعد بيانات منفصلة (Django يستخدم db.sqlite3 و Go يستخدم solarhub_go.sqlite3)؛ أما أشكال المسارات والمخرجات فباتت موحدة.
  • نتائج الاختبار العملي: تم اختبار 53 endpoint GET (عامة + auth + company + admin). النتيجة: 27/53 تطابق كاملاً في HTTP status وشكل الـ response، والـ 26 المتبقية تختلف فقط بسبب غياب بيانات/عضوية الشركة في قاعدة بيانات Go أو أخطاء 500 في Django (مثل GET /api/v1/community/posts/ و GET /api/v1/admin/notifications).
